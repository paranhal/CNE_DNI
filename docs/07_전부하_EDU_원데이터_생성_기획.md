# 07. 전부하(EDU) 원데이터 생성 프로그램 기획

**작성일**: 2025-03-13  
**수정**: 배경·측정방식·요구사항 1·2 재정리, 5개 학교 분석 데이터(CSV) 기반 로직 명시  
**주의**: 기존 ISP 소스는 수정하지 않고, 전부하 전용 소스만 사용.

---

## 0. 기준 데이터 구조 (충남 시트 등)

### 0.1 측정값 3종

| 순서 | 구분 | 비고 |
|------|------|------|
| 1 | **ISP** 측정값 | RTT 열 있음 |
| 2 | **EDU** 측정값 (일반) | RTT 열 있음 |
| 3 | **전부하(EDU)** 측정값 | **RTT 열 없음** (본 프로그램이 원데이터 생성 대상, Mcat=전부하) |

### 0.2 공통 제목행 구조

- **공통 식별 열**: 장비관리번호, 학년, 층, 층,반, AP(또는 AP번호/위치)
- **이어서**: 다운로드(Down 등), 업로드(Up 등), RSSI, CH, (ISP/EDU는 RTT), 진단결과 등
- 제목행에 "다운로드", "Down (Mbps)" 등으로 표기된 열을 다운로드/업로드로 매핑.

### 0.3 제목행 표시 범위

- 시트에 따라 제목행이 **BK열**까지 있음. 선택 화면에서 A~BK(또는 시트 최대 열)까지 표시.

---

## 1. 배경

- **학교당 장비(AP)** 를 **최대 10개**까지 **무작위 선정**하여 측정한다.
- 학교당 **측정 장비 수는 1개 이상 10개 이하**로 다양하다.
- **측정 대수(학교당 장비 수)** 는 **1차·2차 데이터 시트**를 보면 알 수 있다. 시트에서 **학교코드(또는 장비관리번호)** 기준으로 **학교별 행 개수**가 곧 해당 차수의 **측정 장비 수**이다. 1차 시트에 A학교 행이 5개면 1차 측정 시 A학교는 5대, 2차 시트에 A학교 행이 7개면 2차 측정 시 A학교는 7대로 처리한다.
- **1차 측정 장비 수**와 **2차 측정 장비 수**가 **학교별로 다를 수 있다**.
- 측정값은 **1초당 1개**씩 생성된다.

---

## 2. 측정 방식 (전부하)

- **다운로드 측정 1번, 업로드 측정 1번**으로, **총 2번**의 측정을 수행한다.
- 시점 순서:
  1. **1번째 장비** 측정 시작
  2. **20초 뒤** 2번째 장비 측정 시작
  3. 2번째 장비 시작 **20초 뒤** 3번째 장비 측정 시작
  4. … 9번째 장비까지 측정 시작하고 **20초 뒤** 10번째 장비 측정 시작
  5. **10번째 장비 측정이 시작되면** 평균값 산출을 위한 **데이터 수집을 시작**한다.
  6. 각 장비별로 **10분간(600초)** 측정 후 측정 종료 → 장비당 **600개** 데이터.
  7. 이 **600개** 데이터로 각 장비별 **Down, Up, RSSI, CH**의 **평균**을 계산한다.
- 이렇게 산출된 평균이 **1차 측정 데이터 값**과 **2차 측정 데이터 값**이다.

---

## 3. 생성할 원데이터 두 종류 (요구사항)

### 3.1 요구사항 1: 차수별 평균값 기준 600개 데이터

- **목표**: 1차(또는 2차) **차수별 평균값**을 기준으로, **장비당 600개** 원데이터를 생성한다.
- **조건**
  1. **측정값인 평균이 나와야 함**  
     → 생성한 600개의 **평균**이 해당 차수(1차 또는 2차)의 **Down, Up, RSSI, CH 평균값**과 일치해야 한다.
  2. **평균값을 기준으로 한 값의 차이(분산)** 는 **분석용 학교 5개** 실측 데이터(CSV)를 기준으로 로직을 재구성한다.  
     → 5개 학교 CSV에서 산출한 분포·편차 특성을 반영하여, 평균은 유지하면서 개별 600개 값의 흩어짐을 실측에 가깝게 만든다.

### 3.2 요구사항 2: 10번째 장비 측정 전 1~9번 데이터

- **목표**: **10번째 장비가 측정을 시작하기 전** 구간에서, **1번~9번 장비**의 측정 데이터를 생성한다.
- **조건**
  1. **요구사항 1의 데이터 값보다 더 나쁘게 나오면 안 된다.**  
     → “더 나쁘다” = 속도가 더 낮다. 즉, **10분 구간(요구사항 1) 평균보다 ramp-up 구간이 더 낮은 속도로 나오면 안 된다.**  
     → 일반적으로 장비가 늘어날수록 속도는 떨어지므로, ramp-up 구간(1~9번만 측정)의 속도는 **10분 구간(10대 모두 측정) 평균보다 좋거나 같게** 유지한다.
  2. **측정 장비가 늘어날수록 속도는 떨어지는 것이 일반 상식**  
     → 1번만 측정할 때가 가장 빠르고, 2번 추가 시 감소, …, 9번까지 모두 측정 중일 때가 10번 시작 전 구간 중 가장 낮은 속도. 단, 그 값도 **요구사항 1의 600개 평균(차수 평균)보다 나쁘면 안 됨.**

### 3.3 학교당 장비 수 N이 10 미만인 경우

- **N번(마지막) 장비**가 측정을 시작한 시점부터 10분간 600개 수집 → 이 600개의 평균 = 차수 평균.
- **시작 전 구간**: 1번~(N-1)번만 있는 구간. 1번 (N-1)×20개, …, (N-1)번 20개.  
  동일하게 “요구사항 1 평균보다 더 나쁘게 나오면 안 됨”, “장비 늘어날수록 속도 감소” 적용.

## 4. 시간·개수 요약

| 구분 | 시간 | 장비당 개수 | 비고 |
|------|------|-------------|------|
| 장비 시작 간격 | 20초 | - | 1번→…→N번 (최대 10) |
| 10분 구간 (요구사항 1) | N번 장비 시작 후 600초 | **600개/장비** | 평균 = 1차/2차 값 |
| 시작 전 구간 (요구사항 2) | 1번 시작 ~ N번 시작 전 | 1번 (N-1)×20, …, (N-1)번 20개 (N≥2일 때) | 속도 ≥ 차수 평균, 장비↑ 속도↓ |
| 출력 시간대 | 14:30:00 ~ 17:00 이전 | - | 일자 없어도 됨 |

### 4.1 DL/UL 시간 연결 (출력 행 순서·시각)

- **1번·2번 중단 없이 이어짐 (DOWN/UP 동일)**  
  - **DL**: 1번 구간(ramp) DL 종료 직후, **끊김 없이** 2번 구간(10분) DL이 이어짐.  
  - **UL**: 1번 구간(ramp) UL 종료 직후, **끊김 없이** 2번 구간(10분) UL이 이어짐.
- **DL 측정**  
  - 1번 구간 DL: `base_time + 0초` ~ `base_time + (총 ramp DL 행 수 - 1)초`  
  - 2번 구간 DL: **바로 이어서** `base_time + (총 ramp DL 행 수)초` ~ `base_time + (총 ramp DL 행 수 + N×600 - 1)초` (중단 없음)
- **UL 측정**: 2번 구간 마지막 DL이 끝난 시각 **1초 후**부터 UL 시작.  
  - UL 시작 시각: `base_time + (총 ramp DL 행 수 + N×600)초`  
  - 1번 구간 UL → **바로 이어서** 2번 구간 UL (중단 없음)

---

## 5. 출력 형식·기술 규칙

- **출력 열**: 전부하 샘플과 동일 + **W열 평균값 데이터**
  - A~V: Date, StartTime, 학교, 학년, 반, 메모1, 메모2, 측정순번, 측정유형, 측정서버, DL, UL, RTT, LOSS, SSID, BSSID, Standard, CH, Freq., RSSI, BW, 학교코드
  - **W. 평균값 데이터**: **2번 구간(평균용 측정, 10분 600개/장비)** 행에만 "평균값 데이터" 표기. 1번 구간(ramp) 행은 빈칸.
- **전부하**: 측정유형=전부하, 측정서버=EDU, **RTT=빈 값(전 구간)**.
- **CH → Freq.**: CH 36 → 5180, CH +1 → Freq. +5 (CH 100 → 5500).
- **Standard**: 802.11ax.

## 6. 구현 시 유의사항

1. **5개 학교 분석 CSV**: 실측 전부하 데이터 5개 학교 CSV를 기준으로, 600개 값의 **분산·범위** 로직을 구성한다. 프로그램 실행 시 "5개 학교 전부하 측정 CSV가 있는 폴더" 경로를 입력하면, 해당 폴더 내 `*.csv`를 읽어 장비(memo1)별 DL_Mbps, UL_Mbps, RSSI의 평균·표준편차를 산출하고, 계수 of variation(CV) 및 RSSI 표준편차를 600개 생성 시 반영한다. CSV 미입력 시 기본 분산 규칙 사용.  
   - **권장 폴더**: `raw_data/전부하_측정자료_5학교/` (같은 형식의 CSV 5개 배치).
2. **요구사항 1**: 장비별 600개 생성 시 **평균이 차수 평균과 정확히 일치**하도록 합 보정. Down, Up, RSSI, CH 모두 적용.
3. **요구사항 2**: ramp-up(1~9번) 구간의 속도는 **해당 장비의 차수 평균(요구사항 1 기준)보다 나쁘지 않게** 생성. 20초마다 장비 추가 시 속도는 감소하되, **차수 평균 미만으로 떨어지지 않도록** 상한/하한 적용.
4. 학교당 최대 10대, 10대 미만·1차/2차 장비 수 상이는 기존과 동일하게 처리.
5. 선택 화면: 제목행 A~BK(또는 시트 최대 열) 표시.

## 7. 정리

| 구분 | 내용 |
|------|------|
| **배경** | 학교당 AP 최대 10대 무작위, 1~10대 다양, 1차/2차 장비 수 상이 가능, 1초당 1개 |
| **측정 방식** | DL 1회·UL 1회(총 2회), 20초 간격 1~10번 시작, 10번 시작 후 10분간 600개/장비 → 평균 = 1차/2차 값 |
| **요구사항 1** | 차수별 평균 기준 600개 생성, 평균 일치, 5개 학교 CSV 기반 분산 로직 |
| **요구사항 2** | 10번 전 1~9번 데이터, 차수 평균보다 나쁘지 않게, 장비↑ 속도↓ |
| **RTT** | 전부하 전 구간 빈 값 |

## 2. 1차 목표: 1차·2차 측정 데이터 → 원데이터 추정·산출

### 2.1 배경

- 현재 **1차·2차 데이터**는 **원데이터의 평균값**으로 되어 있음.
- 그 평균을 만든 **원데이터가 없어서**, 이를 **추정해 새로 생성**해야 함.
- 생성 기준은 기획에서 정한 규칙 적용.

### 2.2 원본 데이터 보존 (필수)

- **측정 데이터의 원본은 절대 바꾸면 안 됨.**  
- **평균값이 나오게** 만들 뿐이며, 원본 시트/원본 셀을 수정하지 않음. 생성은 **새 출력 파일**에만 함.

### 2.3 ISP 측정 구조 (6회 측정 = 다운로드 3번 + 업로드 3번)

장비별로 **6번 측정**하며, **다운로드 3번·업로드 3번**만 생성함. **다운로드 6번·업로드 6번** 값을 생성하면 안 됨.

| 회차 | 측정 항목 | 생성 개수 |
|------|-----------|-----------|
| 1차 | 다운로드 값 | DL 1개 |
| 2차 | 업로드 값 | UL 1개 |
| 3차 | 2번째 다운로드 값 | DL 1개 |
| 4차 | 2번째 업로드 값 | UL 1개 |
| 5차 | 3번째 다운로드 값 | DL 1개 |
| 6차 | 3번째 업로드 값 | UL 1개 |

→ **DL 3개, UL 3개**만 생성. 이들의 **평균**이 현재 1차 데이터의 다운로드/업로드와 일치.  
→ **RTT, RSSI만** 6회 측정 행마다 각 1개씩 **6개** 생성함.

### 2.4 사용자 선택 구조 (이전 버전과 동일)

1. **실행 폴더의 파일 이름**을 보여주고 → **실행할 파일**을 사용자가 선택.
2. 선택된 파일의 **시트**, **제목 열**, **일부 데이터**를 보여주고 → 사용자가 선택.

추가로:

- **측정 자료에 대한 열**은 **프로그램 실행자가 선택**.
  - 샘플 데이터의 **제목열 값**이 **어떤 측정 항목과 동일한지** 매핑해서 선택.
- **학교코드** 열도 **프로그램 실행자가 선택**.

### 2.5 생성할 6개 원데이터

- 선택된 데이터를 기준으로, **ISP 측정 데이터의 평균값**이 나오도록 **6개의 원데이터**를 생성.
- **채널(CH)** 값은 **모두 동일**하게 둠.

### 2.6 원데이터 값·시간 규칙 (재기획 반영)

**요지**: 생성된 6개 값이 “인위적으로 만든 데이터”처럼 보이지 않도록, **평균은 원본과 일치**시키되 **개별값은 10~60 구간에서 자연스럽게 분산**되어야 함. “사이값만 나오게” 하지 말고, 원본 평균이 나오는 **여러 개의 자연스러운 측정값**을 만들 것.

#### 값 규칙 (고정값)

| 항목 | 규칙 | 비고 |
|------|------|------|
| **다운로드/업로드 속도** | **10 ~ 60 Mbps** 사이, 개별값마다 자연스러운 차이 | 아래 2.5.1 상세 |
| **RTT** | **0.7** 고정 | 소수점 2자리 |
| **RSSI** | **-1** 고정 | |
| **일자** | 없어도 됨 | |
| **시간** | **14:00:00**부터 시작 | |

#### 소수점

- 모든 숫자(다운로드, 업로드, RTT, RSSI 등)는 **소수점 둘째 자리**까지 표기.

#### 2.6.1 다운로드/업로드 생성 규칙 (상세)

1. **평균 보존 (필수)**  
   - 원본 1차/2차 데이터의 해당 행에 있는 **다운로드 평균값**, **업로드 평균값**이 있다.  
   - 생성하는 **6개 값**(DL 3회, UL 3회)의 **평균**은 반드시 이 원본 평균과 일치해야 한다.  
   - 즉, “10~60 사이 아무 값”만 넣는 것이 아니라, **원본 데이터를 대체하지 않고**, 그 평균이 나오는 **원데이터 6개**를 만드는 것이다.

2. **개별값 범위**  
   - 각 다운로드 값·업로드 값은 **10 Mbps 이상 60 Mbps 이하**로 생성한다.

3. **자연스러운 분산 (단조로움 방지)**  
   - 다운로드/업로드 속도 차이가 **너무 단조롭지 않도록** 한다.  
   - 누가 봐도 “데이터 값을 만든 것 같다”고 느끼지 않도록, 10~60 구간에서 **고르게 분산**되되, 위 평균 조건을 만족하도록 생성한다.  
   - 예: 평균 40일 때 (35, 40, 45)처럼 비슷한 값만 나오지 않게 하고, (예: 12.30, 48.70, 59.00)처럼 높은 값·낮은 값이 섞이도록 한다. (숫자는 예시이며, 합이 3×평균이 되도록 조정.)

4. **구현 시 유의**  
   - “사이값”(10~60 범위)만 반복해서 넣거나, 원본 평균을 무시하고 범위 값만 채우지 말 것.  
   - **3개 DL 합 = 3×원본_DL평균**, **3개 UL 합 = 3×원본_UL평균**을 만족하면서, 각 값이 10~60에서 **랜덤에 가깝게 분산**되도록 알고리즘 설계.
   - **원본 평균이 60을 넘는 경우**(예: 878.46): 개별값은 평균 주변 구간(예: avg×0.85 ~ avg×1.15)에서 생성해 **평균이 원본과 동일**하게 나오도록 한다.
   - **RTT, RSSI**: **RTT·RSSI만** 6개씩 생성(6회 측정 행마다 1개). **6개 평균 = 해당 장비의 원본 RTT·RSSI 평균**이 되도록 구간 설정. RTT는 원본 값 크기에 따라 구간 조정(예: 0.7이면 ±0.2, 16이면 ±2). RSSI는 원본 기준 ±3(예: -52면 [-55,-49]). 소수점 2자리.

#### 시간대·학교 이동

- **지역별 첫 번째 학교 시작 시각**을 기준.
- **학교 간 이동 시간**: **30분**.
- 지역 내 **모든 학교**에 대해 **14:00 ~ 17:30**처럼 데이터가 만들어지도록 함.
- **마지막 데이터는 17:00 이전에 반드시 종료** (17:30에 맞추기보다 17:00 전 종료가 필수).

## 3. 이후 단계: 전부하 데이터

- 위 **1차·2차 원데이터 생성** 출력이 끝난 뒤, **전부하 데이터** 작업 진행.
- **1차·2차 데이터 선택하는 기준**(파일 선택, 시트·제목열·데이터 선택, 학교코드 선택)은 **동일**.
- **측정값을 생성하는 기준**만 1차/2차와 **약간 다르게** 적용 (추후 기획 보완).

1. **실행 파일 형태**로 배포할 것.
2. **제목행 + 일부 데이터 표시 후 사용자 선택** 방식 유지 (이전 버전과 동일).
3. **소스 파일 삭제 금지**: 빌드/기능에 사용한 소스는 삭제하지 말 것.
4. **데이터 경로**: `row_data` 폴더, 기초 데이터 `충남_무선속도_통합_머지파일_보고서용_ver38_20260304_전부하포함_Y1.xlsm` 기준.
5. **충남·대전 동일 로직**: 같은 프로그램으로 두 지역 모두 처리.
6. **마지막 측정 종료**: 17:30이 아니라 **17:00 이전**에 끝나도록 할 것.
7. **값 생성**: 평균은 원본과 일치, 개별 DL/UL은 10~60 Mbps에서 **자연스럽게 분산** (단조로움 방지). **소수점 2자리**.
